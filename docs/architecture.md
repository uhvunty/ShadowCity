# ShadowCity architecture notes

## Components

### Frontend
React renders the control panel, Leaflet map, risk overlays, facilities, road network and scenario metrics. It sends scenario parameters to Django and renders the returned GeoJSON.

### Backend
Django REST Framework validates requests, calls the simulation engine, stores scenario runs in SQLite for easy setup, and serves the neighbourhood data. SQLite is used for the hackathon starter; PostgreSQL/PostGIS is the recommended production direction.

### Simulation engine
The included flood score is a transparent heuristic:
`score = 0.30*low_elevation + 0.25*drainage_blockage + 0.20*rainfall + 0.15*slope_susceptibility + 0.10*historical_evidence`

All factors are normalised to 0–1. Weights and thresholds are demonstration assumptions, not scientifically calibrated coefficients.

Road closure analysis builds a NetworkX graph from road segments. It removes closed/affected edges, then calculates facility reachability and shortest available paths.

### AI explanation
The optional Gemini integration receives already-computed metrics and explains them in plain language. Numerical claims remain generated by deterministic Python code.

## Data contract
Geometries use GeoJSON in WGS84 (EPSG:4326). Coordinates are `[longitude, latitude]`.

## Safety and validation
The current flood model is not a hydraulic model and must not be represented as a real flood forecast. Use real data, calibration, domain review and appropriate validation before any operational use.
